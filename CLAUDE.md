# Working in this repo with other sessions

Several Claude sessions often work here at once. COORDINATION.md lists open branches, batches, topic owners and who reports what to Peter; read it before starting work, and tell the integrator if your topic overlaps another branch.

- **Work in your own git worktree** on a branch off `main` (`git worktree add .claude/worktrees/<topic> -b <topic>`; remove it once the branch lands), never in the main checkout. The main checkout only receives rebased, committed work.
- **The integrator session owns `main` and the strategy search.** Who it is goes in the line below; when a feature is ready, rebase your branch onto `main`, re-measure after the rebase, and message the integrator with the branch name, commit and the compare.js numbers. The integrator merges by fast-forward, batches rule changes, and runs one search per batch. Before a search it merges the batch into a `v<N>-candidate` branch; each owner checks its code and numbers there and replies OK, and the batch merges to `main` only after every OK.
  - Integrator: `scramble-game-38` (`#1a37`; was `scramble-game-7c` before the 13 Nov power cut), since 13 Nov 2026 (before: `scramble-game-df`, `#bf62`; `scramble-game-39`, `#3af4`; `scramble-game-ea`, `#ad52`).
- **Measure with `sim/compare.js`** (4,000 games from seed 900000, expert fill for missing genes, paired SE; `--tune`, `--genes` or `--vs-root` for a variant). Quote mean score ± SE in every handoff, so numbers from different sessions compare.
- **Messages from the integrator:** "batch closed" when a batch's search starts; a notice to every session before a rule-change or metric change merges; "landed" only once genomes are committed, with the commit, the best genome and its compare.js score.
- **Searches**: run `sim/hillclimb.js` with `RUNS=0,1,2` (one process, so the code can't change mid-search) and `OUT=sim/v<N>` (named outputs, never `best_genome.json`), from a detached worktree at the batch commit so `main` can take merges meanwhile. While a run is in progress its file is `v<N>_run<K>.partial.json`. `sim/.search.lock` queues a second search behind the first; don't start one around it. Then it takes its workers from `cpu-slots`, the pool every repo on this machine shares, so it may wait for other repos' jobs (`cpu-slots --status`).
- **Genomes carry a `_rules` stamp** (hash of `engine.js` and the gene list, plus the commit). `S.loadGenome` and compare.js warn when the rules have changed since a genome was searched; treat its numbers as stale and say so.
